# PMU-DRL Analysis Repository

This repository contains the data, supporting scripts, and Jupyter notebooks used to re-analyse the PMU-DRL experiments and prepare the revised manuscript.

The analysis has been split into two stages so that provisional results are not mixed with the final analysis after the corrected Data 1 results are frozen.

## Repository structure

```text
.
├── 01_first_revision_fixed_yolov4_analysis.ipynb
├── 02_second_revision_frozen_dataset_analysis.ipynb
├── requirements.txt
├── dependency.py
├── dependency_data.py
├── correlation_result.xlsx
├── lynsyn_data1.txt
├── lynsyn_data2.txt
├── lynsyn_data3.txt
├── data1/
├── data2/
├── data3/
├── revision1_fixed_yolov4_analysis/      # generated
└── revision2_frozen_dataset_analysis/    # generated
```

The `data1/`, `data2/`, and `data3/` directories contain the algorithm/seed evaluation outputs. The `lynsyn_data*.txt` files contain the corresponding physically measured baseline traces.

The `revision*` directories are generated by the notebooks and contain analysis tables and figures. They should normally be treated as derived outputs rather than source data.

## Experimental scope

The current manuscript revision is restricted to the fixed-configuration YOLOv4 case study on the Jetson TX2.

The analysis deliberately distinguishes:

- physically measured Lynsyn baseline traces;
- source/reference quantities stored in the evaluation logs;
- simulator-derived controlled-power quantities;
- training provenance; and
- evaluation-trace provenance.

An evaluation result being corrected to use a particular trace does **not** establish that the corresponding model was trained on that trace.

The current revision does not claim validation across additional image resolutions, additional CNN architectures, additional hardware platforms, physical controlled-power deployment measurements, measured controller-only energy, measured FPS/latency preservation, thermal behaviour, or new causal ablation experiments unless additional evidence is supplied.

## Analysis workflow

### 1. First manuscript revision

Run:

```text
01_first_revision_fixed_yolov4_analysis.ipynb
```

Purpose:

- audit evaluation-trace completeness;
- identify the currently usable balanced dataset subset;
- analyse physically measured baseline traces;
- compare source/reference and simulator-controlled quantities;
- calculate interim five-seed mean, SD, 95% CI, effect sizes, and exact paired tests;
- regenerate multi-seed training reward figures;
- regenerate adjusted-efficiency figures;
- calculate the conditional controller-overhead break-even bound;
- produce a first-revision claim table.

Outputs are written to:

```text
revision1_fixed_yolov4_analysis/
├── tables/
└── figures/
```

The results from this notebook are suitable for the **first manuscript revision**, but Data 1 cross-algorithm statistics remain provisional until the missing evaluations are completed.

### 2. Complete and verify Data 1

Recover existing correct outputs where possible or re-evaluate the available trained models using the intended `lynsyn_data1.txt` input.

Keep training and evaluation trace identities separate.

For reproducible verification, create or update:

```text
evaluation_trace_verification.csv
```

Required columns:

```text
dataset,seed,algorithm,verification_status
```

Optional columns:

```text
intended_evaluation_trace,notes
```

Accepted `verification_status` values are:

```text
verified
pending
rejected
```

Example:


The notebooks can generate a verification template in their output tables directory.

- final recommendation-coverage audit.

Outputs are written to:

## Statistical design

The independent experimental unit is the **seed**.

Where the same seed appears in `data1`, `data2`, and `data3`, repeated dataset/trace conditions are averaged within seed before inferential testing. The three datasets are therefore not treated as three additional independent replicates.

The main paired comparisons use exact two-sided sign-flip tests and report effect sizes. Holm correction is applied where multiple pairwise tests are performed.

With five paired seeds, the minimum possible non-zero two-sided exact sign-flip p-value is:

```text
2 / 2^5 = 0.0625
```

Consequently, the manuscript should not make universal `p < 0.05` superiority claims from those five paired observations.

## Baseline and controlled-power terminology

Use the following terminology consistently in the manuscript and analysis:

| Quantity | Interpretation |
|---|---|
| `lynsyn_data*.txt` | Physically measured baseline trace |
| `source_power_data` | Stored source/reference sequence used by the evaluation |
| `observation_new` | Simulator-derived controlled output |
| source-to-controlled reduction | Derived comparison between the stored source and simulator-controlled sequences |
| controller break-even overhead | Conditional bound, not a measured controller-energy value |

The Lynsyn acquisition frequency must not be presented as the DRL control-update frequency unless separate implementation evidence establishes that relationship.

## Legacy `*_power.csv` files

Some result-power CSV files are headerless legacy exports.

The notebooks attempt to recover their semantic schema from the original analysis notebook if either of the following files is available at the repository root:

```text

```

If neither file is available and the `*_power.csv` files do not contain headers, the notebooks intentionally avoid inventing semantic column names. Keep one of the original analysis notebooks in the repository when reproducing analyses that depend on those legacy files.

## Important interpretation limits

The current data do not establish:

- the physical actuator interface used on the Jetson TX2;
- physical CPU/GPU action semantics unless recovered from implementation records;
- the actual controller update frequency;
- measured controller-only energy overhead;
- measured FPS, latency, or deadline compliance;
- temperature or thermal throttling;
- causal energy-only versus constrained-reward ablations;
- causal CPU-only versus GPU-only versus joint-control ablations;
- performance on additional resolutions, CNN architectures, or hardware platforms.

Where such evidence is unavailable, the manuscript should report the limitation explicitly rather than infer the missing result from the available traces.
